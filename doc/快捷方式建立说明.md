# ArduPilotLog 桌面快捷方式建立说明

> 环境:Ubuntu 24.04 (GNOME, X11) · 程序目录:`/home/sugar/0_ArduPilotLOG` · 建立日期:2026-10-15

## 原理

Linux 应用菜单的"快捷方式"由三部分组成:

| 组成 | 位置 | 作用 |
|---|---|---|
| 启动脚本 | `0_ArduPilotLOG/ardupilotlog-start.sh` | 设置 `LD_LIBRARY_PATH` 等环境变量后启动主程序 |
| 图标 | `~/.local/share/icons/hicolor/<尺寸>/apps/ardupilotlog.png` | 应用列表里显示的图标 |
| 启动项 | `~/.local/share/applications/ardupilotlog.desktop` | 菜单入口,指向脚本和图标 |

**关键点**:`.desktop` 里的 `Exec` 和 `Icon` 必须能被系统找到——`Exec` 写绝对路径,图标放到 hicolor 图标目录里用短名引用。

## 建立步骤

### 1. 安装图标

先准备一张 128×128 的 PNG(项目里的 `a28.ico` 需转换):

```bash
mkdir -p ~/.local/share/icons/hicolor/128x128/apps
python3 -c "
from PIL import Image
img = Image.open('/home/sugar/0_ArduPilotLOG/logo.png').convert('RGBA')
w = max(img.size)
sq = Image.new('RGBA', (w, w), (255,255,255,255))   # 补成正方形白底
sq.paste(img, ((w-img.width)//2, (w-img.height)//2))
sq = sq.resize((128,128), Image.LANCZOS)
sq.save('/home/sugar/.local/share/icons/hicolor/128x128/apps/ardupilotlog.png')
print('ok')
"
```

(如果直接有现成 PNG,`cp` 过去改名为 `ardupilotlog.png` 即可。)

### 2. 创建启动项

写入 `~/.local/share/applications/ardupilotlog.desktop`:

```ini
[Desktop Entry]
Type=Application
Name=ArduPilotLog
GenericName=ArduPilot Log
Comment=Read ArduPilot binary log
Icon=ardupilotlog
Exec=/home/sugar/0_ArduPilotLOG/ardupilotlog-start.sh
Path=/home/sugar/0_ArduPilotLOG
Terminal=false
Categories=Utility;
```

注意:
- `Exec` 用**绝对路径**(项目自带的 desktop 文件写的是相对路径,菜单里点了找不到程序)
- `Path` 设为程序目录,保证工作目录正确

### 3. 刷新缓存

```bash
chmod +x /home/sugar/0_ArduPilotLOG/ardupilotlog-start.sh
update-desktop-database ~/.local/share/applications
gtk-update-icon-cache -f -t ~/.local/share/icons/hicolor
```

**⚠️ 大坑**:`gtk-update-icon-cache` 必须带 **`-t`** 参数!用户级 `~/.local/share/icons/hicolor/` 默认没有 `index.theme`,不加 `-t` 会静默失败,`icon-theme.cache` 不会生成,GNOME 就永远找不到新图标(屏幕上看不到任何报错)。

### 4. 验证

```bash
# 图标能否被解析(应输出 png 路径)
python3 -c "
import gi; gi.require_version('Gtk','3.0')
from gi.repository import Gtk
i = Gtk.IconTheme.get_default().lookup_icon('ardupilotlog', 128, 0)
print(i.get_filename() if i else 'NOT FOUND')"
```

X11 会话下图标不刷新可按 **Alt+F2 → 输入 `rt` → 回车**重启 GNOME Shell(Wayland 只能注销重登)。

模拟点击菜单图标:`gio launch ~/.local/share/applications/ardupilotlog.desktop`

## 踩坑记录:点击图标没反应

### 排查入口

```bash
journalctl --user --since "10 min ago" | grep -iE "ardupilot|error while loading"
```

本次实际遇到的错误:

```
ArduPilotLog: error while loading shared libraries: libQt6QmlMeta.so.6: cannot open shared object file
```

### 原因

程序包 `Qt/libs/` 里的 Qt 库**拷贝不完整**,缺了 6 个库;启动脚本设置的 `LD_LIBRARY_PATH` 找不到它们时,会落回**系统路径**,而系统装的是 Qt 6.4.2,包内是 Qt 6.8.3,两版混用直接崩溃。

| 缺失库 | 来源 |
|---|---|
| `libQt6QmlMeta.so.6*` | Qt 的 QML 元信息库 |
| `libQt6QmlWorkerScript.so.6*` | Qt 的 QML Worker |
| `libQt6QmlModels.so.6*` | Qt 的 QML 模型库 |
| `libicudata.so.73*` `libicui18n.so.73*` `libicuuc.so.73*` | ICU 73(Qt 6.8.3 依赖) |

### 修复

从本机的 Qt 6.8.3 安装目录(版本必须和包内完全一致!)补齐:

```bash
cp ~/Qt/6.8.3/gcc_64/lib/libQt6QmlMeta.so*        ~/0_ArduPilotLOG/Qt/libs/
cp ~/Qt/6.8.3/gcc_64/lib/libQt6QmlWorkerScript.so* ~/0_ArduPilotLOG/Qt/libs/
cp ~/Qt/6.8.3/gcc_64/lib/libQt6QmlModels.so*       ~/0_ArduPilotLOG/Qt/libs/
cp ~/Qt/6.8.3/gcc_64/lib/libicudata.so.73*  ~/0_ArduPilotLOG/Qt/libs/
cp ~/Qt/6.8.3/gcc_64/lib/libicui18n.so.73*  ~/0_ArduPilotLOG/Qt/libs/
cp ~/Qt/6.8.3/gcc_64/lib/libicuuc.so.73*    ~/0_ArduPilotLOG/Qt/libs/
```

### 复查:确认没有库"漏"到系统路径

```bash
cd ~/0_ArduPilotLOG
export LD_LIBRARY_PATH=$PWD/usr/lib/x86_64-linux-gnu:$PWD/Qt/libs
{ ldd ./ArduPilotLog; for f in Qt/libs/libQt6*.so.6*; do ldd "$f" 2>/dev/null; done; } \
  | grep "=> /lib\|=> /usr/lib" | grep -oE "lib(Qt6|icu)[A-Za-z0-9]*\.so\.[0-9.]+"
```

**输出为空 = 所有 Qt/ICU 库都来自包内**,双击直接运行和快捷方式两条路径行为一致。

## 卸载快捷方式

```bash
rm ~/.local/share/applications/ardupilotlog.desktop
rm ~/.local/share/icons/hicolor/128x128/apps/ardupilotlog.png
update-desktop-database ~/.local/share/applications
```
